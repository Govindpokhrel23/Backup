# セキュリティの確認表

このファイルは、アプリを本番で使う前・大きく直した後に、人が目で確かめるための一覧です（2026年11月16日）。
✅ はコードで対策済み。☐ は人が画面で確かめる・設定するもの。

## 1. 鍵（秘密の値）

- ✅ 秘密の鍵はアプリのファイルに入れない（GitHub の Secrets と Cloudflare の Worker だけ）
  - `SUPABASE_SERVICE_KEY`（sb_secret_…）・`GEMINI_API_KEY`（AIza…）・`CLOUDFLARE_API_TOKEN`・`SUPABASE_ACCESS_TOKEN`・`STORE_REPO_TOKEN`・通知の秘密の鍵
- ✅ アプリに入るのは公開してよい値だけ（Supabase の Publishable key・Worker の住所・通知の公開してよい鍵）
- ✅ 本番では「スマホから直接 Gemini」を使えない（鍵をスマホに置かない）
  - Worker の住所が入らなかった時も同じ。前に保存した鍵は、この機械から自動で消す（2026年11月17日）
- ✅ 本番のファイルには見本版（mock-…・見本のパスワード 1234）を入れない（tools/make-site.sh）
- ☐ チャット・メール・スクショに鍵やパスワードを貼っていないか
  - 貼ってしまったら → その鍵を作り直して、古い鍵を消す
- ☐ 使っていない古い鍵が残っていないか（Gemini・Supabase・GitHub のトークン）

## 2. ログイン

- ✅ 初回コードは6けた・7日で使えなくなる・5回まちがえると使えなくなる
- ✅ 初回コードは当てられにくい作り方（gen_random_uuid）
- ✅ 初回コードを比べる時、かかった時間で中身が分からない比べ方
- ✅ 新しいパスワードは8文字以上
- ✅ 同じ初回コードを同時に2回送っても、通るのは1回だけ（ためした回数も同時に数えられる）
- ✅ 同じ場所（IPアドレス）から1分に10回をこえると、初回コードを受け付けない
- ✅ ログアウトすると、このスマホに残した自分のシフトの控えなどを消す（お店の共用タブレット対策）
- ☐ Supabase → Authentication → Sign In / Providers → 「Allow new users to sign up」をオフ
  - アカウントは Worker（初回コード）だけで作るので、外から勝手に作れないようにする
- ☐ 開発者（9000）・店長（1000）のパスワードは、ほかで使っていない長いものか

## 3. データベース（Supabase の決まり RLS）

- ✅ 全部の表で RLS がオン。ほかの会社のデータは見えない
- ✅ 希望：本人と店長だけ見られる
- ✅ 希望：締切をすぎた週・受付が終わった週は、店員はデータベースでも変えられない
- ✅ 勤務：店員は公開した週だけ見られる。書けるのは店長だけ
- ✅ 時給・人ごとのルール・AIの下書き：店長だけ
- ✅ お知らせ：店員はほかの店員に送れない（店長にだけ送れる）
- ✅ 初回コードの表は、アプリからはだれも見られない
- ✅ ログインしていない人（anon）は、表も関数も使えない（2026年11月17日）
- ✅ 店長かどうかは、データベース（RLS・関数）と Worker で決める。ブラウザだけでは決めない
- ☐ もう動いているデータベースに `supabase/updates/` の SQL を「Run」したか
  - `2026-11-16-security.sql` → `2026-11-17-anon.sql` の順
- ☐ 店員の名前・できること％は、同じ会社の店員どうしで見える（シフト表に名前を出すため）。これでよいか

## 4. サーバー（Cloudflare Worker）

- ✅ アプリのサイト（ALLOWED_ORIGIN）以外からは使えない
- ✅ AI は店長だけ。使えるモデルを決めてある・大きすぎる中身はことわる
- ✅ 通知：同じ会社の人だけ。店員は店長あてだけ。宛先のIDの形を確かめる
- ✅ 回数の制限：同じ場所から1分に60回まで（初回コードは10回）。Worker の入れ物ごとに数えるので完全ではない
- ✅ 予想外のエラーの時は、中の文を見せない
- ☐ もっと強い回数の制限が必要になったら：Cloudflare の Rate Limiting binding（wrangler 4.36 以上）を足す
- ☐ Cloudflare → Workers → 使っていない古い Worker（個人のアカウントのものなど）を消したか
