# はじめに読む（初めてこのコードを読む人へ）

このファイルは、プログラムを初めて読む人が「どこに何があるか」「どう動いているか」を分かるようにするための説明です。
くわしい準備のしかたは `README.md`、決めたルールは要件定義書を見てください。

---

## 1. 全体の形（どこからどこへ動くか）

```
 スマホの画面（js/screens/）
      │  画面は「api」だけを使う（データベースを直接さわらない）
      ▼
 js/api/index.js（入口）
      │  config.js の SUPABASE_URL が…
      ├─ 空   → mock-api.js（見本データ。スマホの中だけで動く）
      └─ あり → supabase-api.js（本物。Supabase のデータベース）
                    │
                    ├─ Supabase … データを保存する。「だれが何を見られるか」の決まり（RLS）もここ
                    └─ Cloudflare Worker（workers/api/worker.js）… 管理用の鍵が必要なこと
                          ・はじめての方（アカウントを作る）
                          ・AI（Gemini を呼ぶ）
                          ・プッシュ通知を送る
```

**ポイント**：画面のファイルは、見本でも本物でも同じものを使います。だから画面を直す時は、データの場所を気にしなくて大丈夫です。

## 2. やりたいこと → 見るファイル

| やりたいこと | 見るファイル |
|---|---|
| 色・文字の大きさを変えたい | `css/base.css`（色は一番上の `--` で始まるもの） |
| 画面の見た目を直したい | `js/screens/〇〇.js`（1画面＝1ファイル）と `css/screens.css` |
| 下のタブを変えたい | `js/router.js` の `TABS` |
| 数字の決まり（休憩・連勤・AIのモデルなど）を変えたい | `js/config.js` |
| ルールチェック（必要人数・立ち上げ・休憩など）を直したい | `js/rules/shift-rules.js` |
| 18歳未満・連勤・扶養の上限を直したい | `js/rules/labor-rules.js` |
| AIの下書きを直したい | `js/ai/`（流れは `draft-service.js`、AIに送る文は `prompt.js`） |
| 人件費・働いた時間の計算を直したい | `js/lib/labor.js` |
| 見本データ（スタッフA など）を変えたい | `js/api/mock-data.js` |
| データベースの表を変えたい | `supabase/schema.sql`（変えたら `js/api/supabase/core.js` の入れかえ表も） |

## 3. 1つの操作の流れ（例：店員が希望を保存する）

1. 店員が「希望入力」で「保存」を押す → `js/screens/kibou.js` の `save()`
2. `api.saveMyAvailabilities(週の月曜, 希望の一覧)` を呼ぶ
3. 見本の時 → `js/api/mock-api.js` の同じ名前の関数が、スマホの中（localStorage）に保存
   本物の時 → `js/api/supabase/periods.js` の同じ名前の関数が、Supabase の `availabilities` 表に保存
4. Supabase は `schema.sql` の決まり（`hopes_own`）で「自分の希望だけ書ける」かを確かめる
5. 画面に「保存しました」が出て、前の画面にもどる

**同じ名前の関数が mock と supabase の両方にある**のが大事な所です。新しい機能を足す時は、両方に同じ名前で作ります（テスト `tests/supabase.test.mjs` で本物の方を確かめられます）。

## 4. コメントの読み方

```js
/**
 * ここは「関数の説明」。何をする関数か
 * @param {string} date  受け取るもの（ここでは日付の文字）
 * @returns {number}      返すもの（ここでは数字）
 */
export function example(date) {
  const day = toDate(date);   // ← 行の右の「//」は、その行の説明
  return day.getDay();
}
```

- ファイルの一番上：「このファイルは〇〇のファイルです」＝そのファイルの役目
- `/** 〜 */`：すぐ下の関数・変数の説明
- `// 〜`：その行（または、すぐ下の数行）の説明
- `（2026年11月6日）`：その決まりを足した日。要件定義書と合わせて読む

## 5. 言葉の意味

| 言葉 | 意味 |
|---|---|
| 分で持つ時刻 | 時刻は「0:00から何分か」で持つ。7:00＝420、22:00＝1320、翌1:00＝1500 |
| api | 画面とデータのあいだの「窓口」の関数たち |
| mock（見本） | 本物のサーバーなしで動く、にせものの窓口 |
| Supabase | データを保存する本物のサーバー（データベース） |
| RLS | Supabase の「この人はこの行を見られる・書ける」という決まり |
| Cloudflare Worker | 小さなサーバー。秘密の鍵を使う仕事だけをする |
| Cloudflare Pages | アプリ（HTML・CSS・JS）を公開する場所 |
| PWA | 「ホーム画面に追加」できるWebアプリ |
| サービスワーカー（sw.js） | 電波がない時もアプリを開けるようにし、通知を受け取るプログラム |
| JSON | データを文字で書いたもの（バックアップのファイルなど） |
| CSV | 表を文字で書いたもの（Excel で開ける） |
| 鍵（キー） | サーバーに入るための文字。「画面に置いてよい鍵」と「秘密の鍵」がある |

## 6. 動かし方・確かめ方

- 動かす：VS Code で `index.html` を右クリック →「Open with Live Server」（パスワードは全部 `1234`）
- 確かめる：ターミナルで `npm install`（はじめの1回）→ `npm test`。全部「pass」なら大丈夫

## 7. 直す時の決まり

1. 画面のファイルは `api` 以外からデータを取らない
2. 人の名前などを画面に出す時は `createElement()` を使う（`innerHTML` は使わない＝安全のため）
3. 新しいファイルの一番上には「このファイルは〇〇のファイルです」を書く。変数と関数にはコメントをつける
4. 秘密の鍵（Secret key・Gemini の鍵・通知の秘密の鍵）は、アプリのファイルに絶対に書かない
5. 直したら `npm test` を動かす
